Overview

This is the cumulative final project from my Optimal Control course (MMAE 549), completed during my final semester at Illinois Tech in spring 2026. The project was developed in collaboration with Alec Weedman and covers the full design, implementation, and evaluation of a constrained Model Predictive Controller (MPC) for powered landing of a reusable rocket booster — the same challenge at the core of SpaceX's Falcon 9 booster recovery.

The booster is modeled as a 3D point mass with gravity, atmospheric drag, variable mass from fuel consumption, thrust magnitude limits, and a 20° engine tilt constraint — parameters chosen to roughly represent a Falcon 9 class vehicle during the powered landing phase. The MPC solves a constrained finite-horizon optimization problem at every time step, plans ahead over a 20 second horizon, and re-plans continuously from the current state. A PD baseline controller tracking a pre-planned reference trajectory is used for comparison.

Both controllers are tested in a nominal (no-wind) case and a wind-disturbed case. The MPC achieved a successful soft landing in the nominal case with a final position error of 1.453 m and a final speed of 0.122 m/s. The PD controller did not meet the landing condition in either case.

System Model

Booster Dynamics

The booster is modeled as a simplified 3D point mass. The state vector is position, velocity, and mass: [rx, ry, rz, vx, vy, vz, m]. The control input is the thrust vector [Tx, Ty, Tz]. The equations of motion include gravity, atmospheric drag (via an exponential density model), fuel consumption via the rocket equation, and an optional wind disturbance acceleration.

Attitude dynamics are not modeled — the thrust vector is directly limited by a maximum tilt angle of 20°, which assumes a lower-level attitude controller exists. This keeps the project focused on landing guidance and the controller comparison.

Engine Cutoff Condition

A successful near-touchdown is defined by three simultaneously satisfied conditions: horizontal distance from target ≤ 3 m, altitude ≤ 1.5 m, and total speed ≤ 1 m/s. When all three are met, the engines shut off and the simulation ends. This defines the landing target the MPC is optimizing toward.

Controllers

Model Predictive Controller (MPC)

At every time step, the MPC solves a constrained finite-horizon optimization problem over a 20 second prediction window. It predicts the future booster motion, finds the optimal thrust sequence, applies only the first command, then re-plans from the new state. This receding horizon approach gives the controller closed-loop feedback and allows it to adapt its plan continuously.

The cost function penalizes position error, velocity error, command magnitude, and fuel use at each step, plus a large terminal penalty on final position and velocity error. The optimization is solved in Python using scipy.optimize.minimize, with the previous solution shifted forward as the warm-start initial guess to reduce solve time.

PD Baseline Controller

The PD controller tracks a pre-planned straight-line reference trajectory from the initial position to the landing target. It computes a desired acceleration from position and velocity errors against the reference, then converts this to a thrust command. The same thrust magnitude, tilt, and fuel limits from the MPC are applied to the PD controller, ensuring a fair constraint-consistent comparison.

The key difference from MPC: the PD controller has no lookahead, reacts only to current error, and has no explicit fuel optimization. It was tuned manually to give a competitive reference-tracking response without a meaningful trajectory plan.

Results — Nominal Case

In the nominal (no-wind) case, the MPC successfully met the engine cutoff condition at t = 134 s, reaching a final position error of 1.453 m and a final speed of 0.122 m/s. The PD controller did not meet the cutoff condition and ended with a final position error of 148.734 m and a final speed of 162.09 m/s.

The MPC also used notably less fuel than the PD controller — 26,124 kg vs. 31,892 kg — while achieving far better landing accuracy. The MPC reached the 20° tilt limit to correct horizontal error; the PD controller reached only 3.28° of tilt, which was insufficient to close the horizontal offset before simulation end.

Results — Wind-Disturbed Case

The wind-disturbed case uses a constant lateral acceleration of [0.10, −0.05, 0] m/s² to represent unmodeled external forces. The MPC did not trigger engine cutoff in this case — the final horizontal error of 7.988 m slightly exceeded the 3 m cutoff threshold — but it still ended near the target at low speed (8.294 m position error, 0.502 m/s). The PD baseline ended 162 m from the target at over 162 m/s.

The wind case revealed the main limitation of the current MPC tuning: the controller remained stable and slow, but needed stronger lateral correction to fully overcome the persistent disturbance. Possible improvements include increasing horizontal error penalties in the cost function or lengthening the prediction horizon. Despite not triggering cutoff, the MPC still dramatically outperformed the PD baseline.

My Role

Controller Design & Simulation

  • System model: implemented the 3D point-mass dynamics with gravity, exponential atmosphere drag, fuel burn, and wind disturbance in Python.
  • MPC formulation: designed the cost function (running + terminal penalties on position, velocity, command, and fuel), the thrust parameterization, and the constraint enforcement strategy.
  • Optimization loop: built the receding-horizon solve loop using scipy.optimize.minimize with warm-start initialization from the previous solution.
  • PD baseline: implemented the reference trajectory generator and PD gain tuning for a fair constraint-consistent comparison.
  • Closed-loop simulation: ran both controllers in the nominal and wind-disturbed cases, recorded all performance metrics, and generated the result figures and trajectory animations.

Key Takeaways

  • MPC is well-suited to this constrained landing problem — it can plan ahead, respect physical limits, and optimize fuel use simultaneously, none of which a PD controller can do.
  • The nonconvex nature of the problem means results are not perfectly repeatable between runs; a practical implementation would need faster solvers or a convex reformulation.
  • Wind robustness requires stronger lateral penalties in the cost function or a longer prediction horizon — the current tuning keeps the vehicle slow and near the target but doesn't fully reject the persistent disturbance.
  • This project directly extended my controls and dynamics coursework into an open-ended engineering design problem, connecting optimal control theory to a realistic aerospace application.
